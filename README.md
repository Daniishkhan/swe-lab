# swe/prep

A local study lab for senior software engineer interviews — built to the
**Google L5 (gold standard)** and **Anthropic Senior SWE** hiring bars, with
transferable depth across top engineering loops. High-ROI concepts are built
from first principles with an analogy and interactive visualization in plain
HTML/CSS/JS that runs straight from disk; remaining topics use Socratic `teach`
sessions and timed worksheets. Exercises are Python stubs with work-measuring
tests: you write the solutions.

## Quick start

```bash
open index.html                 # the dashboard; no server or build needed
make setup                      # optional: .venv with pytest
make test                       # run every exercise's tests (they fail until you solve them)
make one K=hash_map             # run one exercise
make progress                   # run tests + show pass counts on the chapter pages
```

No `make`? Use `python3 -m pytest`, `python3 -m pytest -k hash_map`, and
`python3 tools/build.py --run-tests`.

## Priority key

- **P0**: asked almost everywhere (Google L5 + Anthropic + broad senior bar). Do these first.
- **P1**: common at senior level or decisive for leveling.
- **P2**: differentiator or role-specific.

## The track

The home page separates concerns cleanly into four lanes so setup, technical
study, behavioral prep, and company-specific onsite prep never mix—with plain
sequential numbering (`1, 2, 3…`) instead of jumping chapter IDs:

1. **Phase 0 (4 days, before Week 1):** Deep Python warm-up (comprehensions,
   lambdas, closures, lazy generators, data model, gotchas, decorators, context
   managers, and stdlib via `py_idioms`, `py_internals`, and `py_toolkit`), the
   Google bare-editor coding playbook, and your 60-second intro + flagship
   project baseline so early recruiter calls never interrupt technical study.
2. **Weeks 1 to 10 (pure technical spine, ~5h/day):** Zero behavioral or setup
   steps mixed in. **Weeks 1 to 4 make you technical-screen ready** across
   Google (bare-editor DSA), Anthropic (4-level practical + concurrency), and
   general senior loops; **Weeks 5 to 10** build Google L5 system design,
   AI-infra depth, and advanced scale follow-ups.
3. **Parallel Behavioral Track (~1h/week on Sundays):** Runs alongside technical
   weeks (STAR stories, Google G&L, Anthropic Values, Past-Project Deep Dive,
   Hiring Manager, and Senior Behavioral mock) without breaking coding or
   system design flow.
4. **Onsite & Company Packs:** Triggered when an onsite is booked (or Weeks 11
   to 12).

Order matters more than speed: each topic lists what it `requires` in
`curriculum.json`, and `tools/build.py` refuses a track where anything comes
before what it builds on. Each coding topic also lists a few timed `drills`
(LeetCode titles) for two problems a day.

## The study loop

1. Open the concept page. Read the one-sentence idea, then try to predict the
   rest before opening the panes (collapse all with <kbd>c</kbd>).
2. Play with the visualization until you can predict the next step.
3. Answer "Check yourself" out loud before expanding the answers.
4. Do the exercise: read the docstring, say the brute force and its complexity,
   write the solution, run the tests. Then do one or two classic problems.
5. Mark the step `learning` or `confident` on the home page or the chapter
   page (stored in your browser). "Next on your track" moves on when a step is
   confident.

## Using Claude here

Claude Code picks up the skills in `.claude/skills/` on its own. Ask in plain
words:

- "Teach me consistent hashing" or "quiz me on heaps": `teach` builds the idea
  from first principles, then has you explain it back to find the gaps.
- "I'm stuck on `sorts`" or "review my `merge_sort`": `coach` gives one hint
  at a time and never the solution, then reviews working code like an
  interviewer would.
- "Mock interview, system design, 45 minutes": `mock-interview` runs it
  timed, scores it with evidence, and logs it in
  `sections/15-interview-formats/mock-log.md`.

Chapters are written with `write-chapter`, `visuals-and-layout` and
`review-chapter`. `CLAUDE.md` has the rules Claude follows in this repo.

## Adding material

```bash
python3 tools/new.py concept  01.06 tries "Tries and radix trees"
python3 tools/new.py exercise 02.09 mst_kruskal "Minimum spanning tree"
python3 tools/new.py case     "URL shortener"            # §07 worksheet
python3 tools/new.py story    "Led the payments migration"   # §14 STAR story
python3 tools/new.py lld      "Parking lot"              # §10 worksheet
```

Each command copies a template, fills in the topic, and reruns `tools/build.py`
so the new page shows up in the sidebar and chapter page. See
[templates/README.md](templates/README.md) for the page structure and voice.

Exercise module names must be unique across the repo, because pytest imports
them by bare name.

## Keyboard shortcuts (all pages)

<kbd>[</kbd> toggle sidebar · <kbd>t</kbd> next theme (Ayu Dark → Mirage → Light) · <kbd>c</kbd> collapse all panes · <kbd>e</kbd> expand all panes

browser in localStorage.
