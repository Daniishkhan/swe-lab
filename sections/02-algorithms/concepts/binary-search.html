Binary search and "search on the answer"

Binary search isn't really about sorted arrays. It works on any yes/no question whose answer flips exactly once. Find that flip and you can throw away half the possibilities with every guess.

CoreThe one-sentence idea

If a predicate goes false, false, …, false, true, true, …, true over a range, you can find the first true in O(log n) probes. A sorted array is just one place where such a predicate exists.

Build itFrom first principles

1. The real shape: a monotonic predicate

Take ok(i) = nums[i] >= target on a sorted array. As i grows it's F F F T T T. It never flips back. Every binary search question is "where's the first T?" (or the last F).

2. One template, half-open interval

lo, hi = 0, len(nums)          # answer is in [lo, hi]; hi = "none are true"
while lo < hi:
    mid = (lo + hi) // 2
    if ok(mid):  hi = mid        # mid might be the answer; keep it
    else:        lo = mid + 1    # mid is definitely not; drop it
return lo                         # first index where ok is true

The invariant, which you should say out loud: everything left of lo is false, everything from hi on is true. Each step shrinks [lo, hi) and keeps the invariant, so when lo == hi you've found the boundary. No +1/-1 guessing, no infinite loops.

3. Search on the answer

Often you're not searching an array at all. You're searching the space of possible answers: "what's the minimum ship capacity to deliver in D days?" Capacity c either works or doesn't, and if c works, c+1 works too. That's monotonic, so you can binary search c over [max(weight), sum(weights)] with a greedy O(n) check at each probe. Total: O(n log(sum)).

Smell test for this pattern: "minimum X such that…" or "maximum X such that…", plus a check that's easy once X is fixed. Examples: Koko eating bananas, split array largest sum, minimum days to make bouquets, the smallest divisor under a threshold.

IntuitionAnalogy: finding the bad commit

git bisect is binary search on a predicate: "is the bug present at this commit?" Old commits are good, new ones bad, and somewhere it flips. You never need the commits to be "sorted" by anything except time, and you only need the predicate to flip once.

Physical picture: a dimmer switch with an unmarked dial. You want the lowest setting where the room is bright enough. Try the middle, then the middle of the half that's left. Ten tries cover a thousand positions.

InterviewWhat a senior answer adds
  • Name the predicate and prove it's monotonic before writing code. That one sentence is the whole correctness argument.
  • Use one template everywhere and state the invariant. Interviewers watch for lo <= hi vs lo < hi confusion. Having a single template you can defend reads as senior.
  • Overflow: in Java or C++, (lo + hi) / 2 can overflow; write lo + (hi - lo) / 2. Python ints don't overflow, but mention it anyway.
  • Beyond arrays: bisecting a deploy range, searching a timestamp-sorted log file by seeking to byte offsets, finding a capacity limit with load tests. All the same idea.
  • Know the library: bisect.bisect_left / bisect_right, and since Python 3.10 they take a key=.
TrapsCommon mistakes
  • Infinite loop: lo = mid with mid = (lo + hi) // 2 can stall when hi = lo + 1.
  • Wrong search bounds for search-on-answer: the low bound must be feasible-or-below (max weight), the high bound definitely feasible (sum).
  • Using it on a predicate that isn't monotonic, like a "peak" in an unsorted array without the extra argument for why it works.
  • Returning lo without checking it's in range and actually matches (for an exact-match search).
RecallCheck yourself
How do you get the last index where nums[i] ≤ target from the template?

Search the first index where nums[i] > target (bisect_right) and subtract 1.

How does search in a rotated sorted array still work?

At any mid, one half is sorted (compare nums[lo] with nums[mid]). Check whether the target lies inside that sorted half's range; if so go there, otherwise go to the other half.

How many probes for a range of 10⁹?

About 30, since log₂(10⁹) ≈ 30. That's why "n up to 10⁹" in a problem statement is a hint.
