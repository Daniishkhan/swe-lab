Recursion and backtracking

Backtracking is a depth-first walk through a tree of choices that you never actually build. Choose, explore, un-choose. The skill is seeing the tree, and cutting branches before you walk them.

CoreThe one-sentence idea

Make one choice, recurse on the smaller problem, then undo the choice and try the next one. Pruning (abandoning a partial solution that can't succeed) is what makes exponential search finish in practice.

Build itFrom first principles

1. Recursion is delegation with a contract

A recursive function says: "I'll solve this size-n problem by trusting myself to solve a smaller one." You need a base case (small enough to answer directly) and progress (every call gets closer to it). Don't trace the whole call tree in your head. Trust the contract, which is the "leap of faith" that makes recursion manageable.

2. The decision tree

Subsets of [1, 2, 3]: at each level, decide "include this element or not". That's a binary tree of depth 3 with 2³ = 8 leaves, one per subset. Permutations: level k picks which unused element goes in position k, giving n! leaves. Draw the tree first; the code follows from it.

3. The template

def backtrack(path, choices):
    if is_complete(path):
        results.append(path.copy())   # copy! path keeps changing
        return
    for c in choices:
        if not valid(path, c):        # prune
            continue
        path.append(c)                # choose
        backtrack(path, next_choices) # explore
        path.pop()                    # un-choose

4. Pruning is where the speed comes from

N-queens: placing queens row by row and checking columns and diagonals with sets cuts 8-queens from 16.7 million raw placements to about 2,000 visited nodes. Sudoku, combination sum with a sorted list ("stop once the remaining candidates are too big"), and word search all live or die by pruning.

5. When the tree has repeated subtrees, it's DP

If different paths lead to the same subproblem (same index, same remaining sum), cache the result. That's memoization, and it's the bridge to the next page.

IntuitionAnalogy: a choose-your-own-adventure book

At each page you pick an option and turn to it. When you hit a bad ending, you flip back to the last choice and take the other option. Your finger holding the earlier page is the call stack. Un-choosing is flipping back. Pruning is noticing "this path leads into the dragon's cave" and not reading it at all.

InterviewWhat a senior answer adds
  • Draw a small tree before coding and point at what each level decides. Interviewers love seeing the structure first.
  • Handle duplicates by sorting and skipping: if i > start and nums[i] == nums[i-1]: continue. Explain that it prevents identical sibling branches.
  • State the complexity honestly: it's exponential, and that's fine when n is small. Show where pruning helps without claiming it changes the worst case.
  • Production relevance: constraint solvers, schedulers, config validators, regex engines (catastrophic backtracking is a real outage cause: ReDoS), and search over plans in AI agents.
TrapsCommon mistakes
  • Appending path instead of path.copy(): every result ends up as the same (empty) list.
  • Forgetting to un-choose (pop, or remove from the used set) after the recursive call.
  • Missing base case or no progress: infinite recursion.
  • Mutable default arguments (def f(path=[])) leaking state across calls.
RecallCheck yourself
Subsets: "include/exclude" tree vs "for i in range(start, n)" loop. What's the difference?

Same subsets, different tree shapes. Include/exclude makes a binary tree where every leaf is a subset. The loop version emits a subset at every node, where each node picks the next element to add, which naturally avoids duplicates and handles combinations.

How do you generate permutations without a "used" array?

Swap-based: for position k, swap each later element into position k, recurse on k + 1, then swap back.

When should you stop backtracking and switch to DP?

When the state of a subproblem (index, remaining capacity…) is small and repeats across branches. Then caching the answer turns exponential work into (number of states × work per state).
