Two pointers, sliding windows and prefix sums

Three techniques that turn "check every subarray" (O(n²)) into one pass (O(n)). They all work the same way: reuse what you computed for the last position instead of starting over.

CoreThe one-sentence idea

Don't recompute overlapping work. A window slides by adding one element on the right and removing one on the left; a prefix sum answers any range sum as one subtraction.

Build itFrom first principles

1. The brute force and its waste

"Longest substring without repeating characters": check every (start, end) pair, which is O(n²) pairs and O(n) to check each, so O(n³). But the substring [2..7] and [2..8] share almost everything. The waste is recomputing the shared part.

2. Sliding window: grow right, shrink left

left = 0
for right, x in enumerate(items):
    add x to the window state
    while window is invalid:
        remove items[left] from the window state
        left += 1
    record the answer for window [left, right]

Both pointers only move forward, so the total work is O(n) even with the inner while. The window state is usually a counter, a set, or a running sum.

When it works: validity must be monotonic as the window grows. If [l, r] is invalid, then [l, r+1] is also invalid (for "at most" constraints), so moving left is safe. Negative numbers in a sum break this, which is when you switch to prefix sums.

3. Two pointers from both ends

On sorted input, one pointer at each end: if the sum is too big, move the right pointer left; if too small, move the left pointer right. Each move rules out a whole row of pairs. That covers two-sum on sorted input, container with most water, 3-sum (fix one, two-pointer the rest), and palindromes.

4. Prefix sums: precompute once, answer any range in O(1)

P[0] = 0, P[i+1] = P[i] + nums[i]
sum(nums[i..j]) = P[j+1] - P[i]

Combined with a hash map of "how many times have I seen prefix value p?", you can count subarrays summing to k in one pass, negatives included: at each point, ask how many earlier prefixes equal current − k.

IntuitionAnalogies

Sliding window: a caterpillar

The head eats forward. When it's eaten something bad (a repeated letter), the tail inches forward until the bad bit is gone. It never walks backwards.

Two pointers: squeezing a tube of toothpaste

Fingers start at both ends and move inward. Each squeeze permanently rules out the part behind your fingers.

Prefix sums: a car's odometer

To get the distance between two towns, subtract the odometer readings. You never re-drive the road.

InterviewWhat a senior answer adds
  • Justify the O(n): "each index enters the window once and leaves once."
  • Know when the window breaks (negatives, non-monotonic validity) and switch to prefix sums with a hash map. Saying why is the senior part.
  • "Exactly k" = "at most k" − "at most (k−1)": a standard trick for counting windows with exactly k distinct values.
  • The same idea in systems: sliding-window rate limiters, moving averages over metrics, TCP's sliding window for flow control, and 2D prefix sums (summed-area tables) in image processing and analytics.
TrapsCommon mistakes
  • Forgetting to seed the prefix-count map with {0: 1}, which misses subarrays starting at index 0.
  • Recording the answer before the window is valid again.
  • Jumping left to last_seen[c] + 1 without max(left, …): left must never move backwards ("abba").
  • Using a sliding window when the array has negative numbers.
RecallCheck yourself
Fixed-size window of k: what's the template?

Add nums[i], and once i ≥ k, remove nums[i − k]; record the answer when i ≥ k − 1. No inner while loop needed.

Why does sorted two-sum with two pointers never miss the answer?

If sum > target, the right element can't pair with anything at or right of the left pointer (all those are ≥ left), so discarding it loses nothing. The symmetric argument covers the left pointer.

How do you count subarrays with sum divisible by k?

Prefix sums mod k: two prefixes with the same remainder bound a subarray whose sum is divisible by k. Count remainders in a map.
