Heaps and priority queues

When you only ever need the smallest thing, keeping everything fully sorted is wasted effort. A heap keeps just enough order to hand you the minimum in O(1) and repair itself in O(log n).

CoreThe one-sentence idea

A heap is a complete binary tree stored in a plain array, where every parent is no bigger than its children. The minimum sits at index 0, and push or pop fixes the order along a single root-to-leaf path.

Build itFrom first principles

1. What a scheduler actually needs

A job scheduler needs one thing fast: "what runs next?" A sorted array answers that in O(1) but costs O(n) per insert. An unsorted array inserts in O(1) but finds the minimum in O(n). We want both in about O(log n).

2. Weaken the invariant

Full sorting relates every element to every other. A heap only promises parent ≤ child. Siblings and cousins can be in any order. That weaker promise is much cheaper to maintain, and it's still enough to know where the minimum is: at the root.

3. Store the tree in an array, no pointers

Fill the tree level by level, left to right (a "complete" tree). Then the shape is implied by the index:

children of i:  2i + 1, 2i + 2
parent of i:    (i - 1) // 2

No pointers, perfect cache locality, and the tree is always balanced, so its height is ⌊log₂ n⌋.

4. Two repair moves

  • push: put the new item at the end, then sift up: swap with the parent while it's smaller.
  • pop: take the root, move the last item to the root, then sift down: swap with the smaller child while it's bigger.

5. Heapify is O(n), not O(n log n)

To build a heap from n items, sift down every non-leaf from the bottom up. Half the nodes are leaves (no work), a quarter sift at most 1 level, an eighth at most 2… The sum n·(1/4 + 2/8 + 3/16 + …) converges to O(n).

IntuitionAnalogy: a company org chart

Every manager is more senior than their direct reports, but two people on different teams aren't compared at all. When the CEO leaves (pop), the most junior person is temporarily put in the CEO's chair and keeps getting swapped with their more senior direct report until the rule holds again. A new hire (push) starts at the bottom and gets promoted past anyone less senior above them.

Physical picture: bubbles. Light things rise (sift up), heavy things sink (sift down), and each one moves through at most log n levels.

PatternsThe three heap moves interviews love

Top-k

To keep the k largest, use a min-heap of size k. Each new item competes with the smallest of your current top k (the root); if it's bigger, it replaces the root. O(n log k) time, O(k) memory, and it works on a stream.

K-way merge

Merging k sorted lists: put the head of each list in a heap, pop the smallest, push that list's next item. O(N log k). This is how external merge sort and LSM-tree compaction work (chapter 6).

Scheduling / simulation

Keep events keyed by time and always process the earliest. Meeting rooms, task schedulers, Dijkstra (chapter 2), timers in event loops.

Python's heapq is a min-heap. For a max-heap, push -x. To break ties without comparing payloads, push tuples (priority, counter, item).

InterviewWhat a senior answer adds
  • Lazy deletion instead of decrease-key: push a new entry and skip stale ones when you pop them. That's how Dijkstra is usually written with heapq.
  • Top-k at scale: on one machine, use a size-k heap. Across machines, each shard computes its local top-k and a coordinator merges them. With heavy-hitter streams, use approximate structures (Count-Min Sketch + heap). This is a classic system design follow-up.
  • Starvation: a pure priority queue can starve low-priority work forever. Real schedulers add aging, or use separate queues with weighted fairness.
  • Thread safety: heapq isn't thread-safe; queue.PriorityQueue wraps it with a lock.
TrapsCommon mistakes
  • Using a max-heap for "k largest" (you want a min-heap of size k), or the reverse for "k smallest".
  • Pushing tuples whose second element isn't comparable (dicts, custom objects). Ties then crash. Add a counter.
  • Assuming the heap array is sorted. Only index 0 is guaranteed.
  • Sift-down choosing the first child instead of the smaller child.
RecallCheck yourself
Why is a heap stored in an array, but a BST usually isn't?

A heap is always a complete tree, so index arithmetic describes its shape exactly with no gaps. A BST's shape depends on the data; storing it in an array would leave huge holes.

How do you find the median of a stream?

Two heaps: a max-heap for the lower half and a min-heap for the upper half, kept within one element of each other in size. The median is at one or both roots. O(log n) per insert, O(1) per query.

Why does sift-down swap with the smaller child?

The smaller child becomes the parent of the other child, so it has to be ≤ that sibling. Swapping with the larger child would break the invariant right away.
