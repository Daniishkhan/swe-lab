Linked lists, stacks, queues and monotonic stacks

These are all arrays or chains of nodes with one rule about which end you may touch. The rule is the whole point. It's what turns a pile of data into an algorithm.

CoreThe one-sentence idea

A stack touches only the newest item, a queue only the oldest, a deque both ends. A monotonic stack adds one more rule: keep the items sorted by throwing out anything the newcomer makes irrelevant.

Build itFrom first principles

Linked list: trade random access for cheap splicing

An array needs one contiguous block, so inserting in the middle shifts everything. A linked list gives that up: each node holds a value and a pointer to the next node, and nodes can live anywhere in memory.

head → [3 | •] → [7 | •] → [1 | ∅]
  • Splice is O(1) if you already hold the node: rewire two pointers.
  • Finding is O(n): no address arithmetic, you have to walk.
  • Doubly linked (prev and next pointers) lets you delete a node given only the node itself. That's exactly what an LRU cache needs.
  • Sentinel nodes: a dummy head and tail that are never removed. Every real node then has neighbors on both sides, and the "empty list" and "first node" special cases disappear.

Stack (LIFO): only the top

Push and pop at one end. In Python, a list with append/pop() is a perfect stack, O(1) amortized. Stacks show up whenever the most recent unfinished thing must be finished first: function calls, undo, matching brackets, DFS.

Queue (FIFO): in at the back, out at the front

Fairness and order of arrival: BFS, task queues, request buffers. In Python use collections.deque. list.pop(0) shifts every element, so it's O(n) per dequeue.

Deque: both ends

Usually a ring buffer (an array with wrapping head and tail indexes) or a list of fixed-size blocks, which is what CPython uses. O(1) at both ends, and it's the engine of the monotonic queue.

Monotonic stack: a stack with a sorting rule

Before pushing a new element, pop everything it "beats". The stack stays sorted, and every pop is a moment of discovery: the element being popped just met its next greater element. Each element is pushed once and popped at most once, so the whole pass is O(n), even though there's a loop inside a loop.

IntuitionAnalogies

Stack: a pile of plates

You take from the top. The plate at the bottom waits until everything above it is gone.

Queue: a coffee line

First in, first served. Cutting the line (priority) needs a different structure: a heap.

Linked list: a scavenger hunt

Each clue tells you where the next one is. Adding a stop is easy; jumping straight to stop 50 is impossible.

Monotonic stack: waiting for someone taller

People arrive one by one, and each is waiting for someone taller to show up. When a tall person arrives, everyone shorter at the back of the crowd has their answer and leaves. Whoever stays is still waiting, and they're always in decreasing height order.

The stack holds indexes of elements still waiting for an answer, and their values decrease from bottom to top. Watch how each new value pops everything smaller than itself.

InterviewWhat a senior answer adds
  • Linked lists usually lose in practice. Big-O says O(1) insert, but finding the insertion point is O(n) pointer-chasing with cache misses at every hop. Arrays win most real benchmarks. Use a linked list when you already hold a handle to the node and need O(1) removal: LRU caches, the Linux kernel's list_head, free lists in allocators.
  • Bounded vs unbounded queues. An unbounded queue between a fast producer and a slow consumer is a memory leak with a delay. Senior answer: bound it, and decide what happens when it's full (block, drop, or reject). That's backpressure, which you'll meet again in chapter 3.
  • Recognize the monotonic stack pattern from its smell: "for each element, find the nearest element to the left or right that is bigger or smaller." Daily temperatures, stock span, largest rectangle in a histogram, trapping rain water.
  • Recursion is a stack. Deep recursion in Python hits the ~1000-frame limit. Converting DFS to an explicit stack is a common follow-up.
TrapsCommon mistakes
  • list.pop(0) or list.insert(0, x) in a loop: O(n) each. Use deque.
  • Reversing a linked list and losing the rest of it: save next before you rewire.
  • Forgetting to update tail (or head) when removing the last node.
  • Strict vs non-strict comparison in monotonic stacks. With duplicates, < and <= give different answers. Decide which one the problem wants.
  • Storing values on the monotonic stack when you need distances. Store indexes; you can always look up the value.
RecallCheck yourself
Why is the monotonic stack O(n) when it has a while loop inside a for loop?

Count the work per element instead of per iteration. Each index is pushed exactly once and popped at most once, so all the inner loop runs across the whole pass add up to at most n pops.

How do you build a queue from two stacks, and what does it cost?

Push onto an "in" stack. To dequeue, if the "out" stack is empty, pour everything from "in" into "out" (which reverses the order), then pop from "out". Each element moves at most twice, so it's O(1) amortized.

How do you detect a cycle in a linked list with O(1) extra memory?

Floyd's tortoise and hare: one pointer moves 1 step, the other 2. If there's a cycle, the fast one laps the slow one and they meet. If fast reaches the end, there's no cycle.

For sliding window maximum, why a deque and not a stack?

You need to drop elements from both ends: from the back when a bigger newcomer arrives (the monotonic rule), and from the front when the oldest index slides out of the window.
