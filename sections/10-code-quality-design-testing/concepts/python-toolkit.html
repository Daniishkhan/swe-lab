1Five standard-library tools on one shelf

Python ships with "batteries included" — fast, battle-tested tools already built into Python (no external installs needed). Whenever you catch yourself writing a clunky loop around a plain list or dictionary, check whether one of these five tools already does the job for you:

Every one of these lives in Python's standard library — just import and use.

Let's unpack each tool with plain everyday examples and its one main catch to keep in mind.

2Counting and grouping in one line: Counter and defaultdict

1. collections.Counter — instant tallying

Remember writing the 4-line vote-counting loop on Day 1 (counts[food] = counts.get(food, 0) + 1)? Counter does the whole thing in one line — and returns 0 for missing keys without crashing!

from collections import Counter

votes = ["tacos", "sushi", "tacos", "pizza", "tacos", "sushi"]
counts = Counter(votes)       # Counter({'tacos': 3, 'sushi': 2, 'pizza': 1})

counts["burger"]              # 0 (safe — does NOT insert "burger"!)
counts.most_common(2)         # [("tacos", 3), ("sushi", 2)]

Two handy notes on Counter:

  • Zero-count ghosts: if you subtract counts (counts["pizza"] -= 1), "pizza": 0 stays inside the Counter, so len(counts) still counts it! Delete zeroed keys cleanly with if counts[k] <= 0: del counts[k] (or reassign counts = +counts to build a cleaned Counter without zero/negative keys).
  • Tie-breaking: most_common(k) breaks equal counts by first-seen order, not alphabetical order — if you need alphabetical tie-breaking, sort counts.items() with key=lambda pair: (-pair[1], pair[0]) (from Day 2 Part 2!).

2. collections.defaultdict — auto-creating bucket dictionaries

Remember writing if city not in by_city: by_city[city] = [] before appending? defaultdict(list) automatically creates a fresh empty list the first time you touch a missing key:

from collections import defaultdict

people = [("Maya", "NYC"), ("Sam", "LA"), ("Kai", "NYC")]
by_city = defaultdict(list)
for name, city in people:
    by_city[city].append(name)      # no "if city not in by_city:" needed!
# list(by_city.values()) -> [["Maya", "Kai"], ["Sam"]]

Watch one classic trap with defaultdict: even a plain read like if by_city["Boston"]: silently creates "Boston": [] inside your dictionary! Whenever you just want to check whether a key exists without inserting it, write if "Boston" in by_city: (or by_city.get("Boston")).

Use Counter(items) for 1-line frequency counts (deleting keys that hit 0) and defaultdict(list) for 1-line grouping (using k in d for read-only checks so you never accidentally insert empty entries).

You run c = Counter(["a", "b"]) and then c["a"] -= 1. What does len(c) return afterward?

Spot on! Decrementing a count to 0 leaves "a": 0 in the dictionary, so len(c) stays 2. Write if c["a"] <= 0: del c["a"] when you want len(c) to track only active items.

Picture an inventory clipboard listing apples: 1, pears: 1: crossing out 1 and writing 0 next to apples still leaves two rows written on the clipboard! A Counter behaves the exact same way — len(c) stays 2 until you explicitly run del c["a"].

Given groups = defaultdict(list) (currently empty), you run if groups["NYC"]: print("found"). Afterward, what is "NYC" in groups?

Caught it! Any bracket read groups[missing] triggers the default factory and inserts "NYC": []. Use if "NYC" in groups: whenever you want a pure read check.

Think of a filing cabinet that auto-prints a new empty folder the instant you ask for a drawer label: asking for cabinet["Receipts"] inside an if still prints and inserts an empty "Receipts" folder! Use "NYC" in groups to peek without creating an entry.

Now let's fix the slow-front problem you saw on Day 1 when removing from the front of a list.

3Fast queues at both ends: collections.deque

Remember on Day 1 Part 2 when inserting or popping at index 0 of a list forced Python to scoot every remaining fruit over one slot? That makes a plain list painfully slow for a waiting line (queue).

Python's collections.deque ("deck", short for double-ended queue) solves that completely: adding or removing at either the front (appendleft, popleft) or the back (append, pop) takes just 1 quick step — zero shifting!

from collections import deque

# Coffee shop line: new orders join the back, barista serves the front!
line = deque(["latte", "tea", "mocha"])
line.append("matcha")        # joins the back in 1 step
first = line.popleft()       # serves "latte" from the front in 1 step!

# Bonus: fixed-size history buffer with maxlen (oldest drops off automatically!)
recent_songs = deque(maxlen=3)
for s in ["Song 1", "Song 2", "Song 3", "Song 4"]:
    recent_songs.append(s)
# deque(['Song 2', 'Song 3', 'Song 4'], maxlen=3)

Both append (back) and popleft (front) run in 1 quick step without shifting the rest of the line.

One catch with deque: peeking at the ends (q[0], q[-1]) is instant, yet jumping into the middle by index (q[500]) walks link by link! Use a deque for queues and rolling windows, and keep a plain list whenever you read random indices in the middle.

Reach for collections.deque whenever you remove from the front (popleft()) or keep a fixed-size recent history (deque(maxlen=k)). Keep a plain list for middle indexing.

You are simulating a printer queue where 100,000 jobs enter the back and get pulled from the front one by one. Which container and methods should you use?

Spot on! deque.popleft() removes from the front in 1 quick step (no shifting 99,999 jobs left on every turn!), while a set loses arrival order completely.

Think about Day 1's fruit list visualizer: calling list.pop(0) on 100,000 jobs has to scoot 99,999 jobs forward on step 1, 99,998 on step 2, and so on! And a set doesn't keep queue order. deque gives you 1-step append and popleft in arrival order.

A deque always serves whoever arrived first. What if new tasks keep arriving and you always want to serve the most urgent (smallest priority number) next?

4Always grabbing the smallest item: heapq

Picture a busy support desk: new tasks keep arriving with urgency numbers (1 = urgent outage, 3 = routine email), and whenever an engineer is free, they grab the smallest number on the tray. Sorting the entire list every time a new task arrives wastes lots of work. Python's heapq module keeps the smallest item right at slot 0 cleanly as items come and go:

import heapq

tray = []
heapq.heappush(tray, (3, "answer email"))
heapq.heappush(tray, (1, "fix outage"))
heapq.heappush(tray, (2, "patch bug"))

print(tray[0])                  # peek smallest: (1, "fix outage")
first = heapq.heappop(tray)     # pops (1, "fix outage")!
second = heapq.heappop(tray)    # pops (2, "patch bug")!

# Already have a list of numbers? Turn it into a heap in place:
nums = [9, 4, 7, 1, 5]
heapq.heapify(nums)             # puts smallest (1) at nums[0]

Step through pushing and popping urgent tasks below:

Notice heapq doesn't keep the whole list fully sorted — it only guarantees the smallest item is always ready at slot 0 for heappop!

Two essential heapq tips:

  • Need the largest item first (max-heap)? Python only ships a min-heap (smallest first). For numbers, negate them going in (heapq.heappush(h, -score)) and flip the sign back when popping (-heapq.heappop(h))!
  • Breaking ties safely: if you push tuples like (priority, custom_obj) and two items share the same priority, Python tries to compare the second slot (which crashes if custom_obj can't be compared!). Either add a unique sequence counter between them ((priority, seq, custom_obj) with seq += 1 on each push) or use a @dataclass(order=True) from Day 3!
Use heapq (heapify, heappush, heappop) whenever items arrive over time and you repeatedly grab the smallest one. Negate numeric priorities when you want the largest item first.

You want a heap of test scores where heappop always returns the highest score first. How do you do that with Python's heapq?

Spot on! Because -98 < -85, negating numbers makes the largest original score sit right at the top of Python's min-heap — flip the sign back when popping to get 98.

Picture a thermometer: +30° is hotter than +10°, yet flipping the signs gives -30° < -10° — so a min-heap (which only pops the smallest value and has no max=True flag) pops -30 first! Negate on push and negate again on pop.

Now let's look at our fifth tool: instantly locating values — or counting how many items fall in a range — inside a list that is already sorted.

5Instant lookup in a sorted list: bisect

When you look up "zebra" in a paper dictionary, you don't start at page 1 and flip one page at a time — you jump straight to the middle, cut the remaining pages in half, and find it in a handful of flips! Python's bisect module does that exact jump on any sorted list:

  • bisect_left(nums, x): returns the first index where x could go — everything to its left is strictly < x, and everything from that index onward is >= x.
  • bisect_right(nums, x): returns the first index strictly past any copies of x — everything to its left is <= x, and everything from that index onward is > x.
from bisect import bisect_left, bisect_right

prices = [10, 20, 20, 20, 35, 50]

bisect_left(prices, 20)     # 1  (first 20 is at index 1)
bisect_right(prices, 20)    # 4  (first item > 20 is 35 at index 4)

# How many prices fall between $15 and $40 inclusive? ONE subtraction!
lo, hi = 15, 40
count = bisect_right(prices, hi) - bisect_left(prices, lo)
# 5 - 1 = 4  (the four prices: 20, 20, 20, 35!)

Two catches to remember with bisect:

  • The list MUST be sorted first! Calling bisect on an unsorted list won't crash — it quietly returns a wrong index! If your input isn't sorted yet, run s = sorted(values) once up front (leaving the caller's original list untouched).
  • Guard empty inverted ranges: if a query asks for lo > hi (like lo = 50, hi = 10), return 0 immediately so bisect_right - bisect_left can't go negative!
On a sorted list, bisect_left finds the first slot >= x and bisect_right finds the first slot > x. Count values in [lo, hi] inclusive with bisect_right(s, hi) - bisect_left(s, lo) (guarding lo > hi).

Given the sorted list nums = [2, 5, 5, 5, 9], what do bisect_left(nums, 5) and bisect_right(nums, 5) return?

Spot on! Notice how nicely that matches Python's half-open slicing rule: the three 5s sit at indices 1, 2, 3 (nums[1:4]), so bisect_right - bisect_left = 4 - 1 = 3 gives the exact count!

Check on a tiny list [10, 20, 30] searching for 20: bisect_left lands on index 1 (where 20 starts), and bisect_right lands right after 20 at index 2 (where 30 sits), so 2 - 1 = 1 copy of 20. Same rule on [2, 5, 5, 5, 9] gives 1 and 4.

6Everyday practical helpers and four toolkit gotchas

Beyond collections and searching, three standard-library modules make daily Python scripts dramatically cleaner (see Python Cheatsheet §15 for full examples):

from pathlib import Path
import json
import math

# 1. Clean file paths & line-by-line reading (never loads a giant file all at once!)
log_file = Path("data") / "app.log"
with log_file.open(encoding="utf-8") as f:
    for line in f:
        print(line.strip())

# 2. JSON strings <-> Python dicts/lists (loads/dumps = string; load/dump = file)
text = json.dumps({"user": "Maya", "score": 95})
data = json.loads(text)

# 3. Exact integer math
math.gcd(12, 18)        # 6 (greatest common divisor)
math.isqrt(26)          # 5 (exact integer square root — no float rounding bugs!)

Four quick toolkit gotchas to keep on your radar:

  1. arr.sort() returns None: it edits arr in place — use sorted(arr) whenever you want a new sorted list.
  2. Counter keeps zero counts: delete keys that drop to 0 if len(c) matters.
  3. defaultdict inserts on bracket reads: check if k in d: for read-only lookups.
  4. bisect needs sorted input: sort a copy first (sorted(values)) and guard lo > hi so range counts never go negative.

You run prices = [5, 2, 8] and then ordered = prices.sort(). What does ordered hold?

Spot on! prices itself is now [2, 5, 8], and ordered is None. Write ordered = sorted(prices) whenever you want a sorted copy back!

Python follows one steady convention: methods that edit a list in place (.append(), .reverse(), .sort()) return None to remind you they changed the original box! So ordered = prices.sort() sets ordered to None; use ordered = sorted(prices) instead.
