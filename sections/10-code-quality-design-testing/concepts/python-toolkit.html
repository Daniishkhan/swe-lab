1The hidden O(n) traps inside plain Python lists

You write a clean BFS queue using a plain Python list and queue.pop(0). On a 10-node test graph it passes instantly. On a 300,000-node input, every pop(0) slides 300,000 pointers left—about 45 billion moves. Your O(n) algorithm quietly became O(n²).

You run a round-robin scheduler over 200,000 jobs, popping from the front and pushing back to the tail. Why does deque finish in milliseconds while list.pop(0) times out?

Exactly. Removing index 0 from a contiguous array shifts all n - 1 elements left; a doubly-linked block deque simply advances its head pointer in O(1).

A Python list is a contiguous array: deleting slot 0 forces slot 1→0, 2→1, …, 199,999→199,998 on every single turn. A deque supports O(1) operations at both ends.

2collections: Counter, defaultdict, deque

from collections import Counter, defaultdict, deque

# 1. Counter: instant frequency map (+ subtraction & top-k!)
freq = Counter(["b", "a", "b", "c", "a", "b"])  # {'b': 3, 'a': 2, 'c': 1}
freq["missing"]                                  # 0 (no KeyError!)

# 2. defaultdict: graph adjacency lists & grouping with zero boilerplate
graph = defaultdict(list)
for u, v in edges:
    graph[u].append(v)

# 3. deque: O(1) queue & monotonic deque (maxlen auto-evicts oldest!)
q = deque([start])
cur = q.popleft()
Gotcha on defaultdict: reading d[missing] creates the key with a default value! Use if k in d: or d.get(k) when checking membership without mutating the dictionary.

3heapq: min-heaps, max-heaps & top-k

Python's heapq is a min-heap stored in a plain list. You only need five patterns to cover 95% of Google and Anthropic heap problems:

import heapq

# 1. Build a heap in O(n) (faster than n pushes = O(n log n)!)
nums = [5, 1, 9, 3]
heapq.heapify(nums)               # in-place min-heap: nums[0] is min

# 2. Push / pop in O(log n)
heapq.heappush(nums, 2)
smallest = heapq.heappop(nums)

# 3. Max-heap for numbers: negate on push and negate back on pop
max_h = []
heapq.heappush(max_h, -val)
largest = -heapq.heappop(max_h)

# 4. Top-k largest in O(n log k): keep a MIN-heap of size k
top_k = []
for x in stream:
    heapq.heappush(top_k, x)
    if len(top_k) > k:
        heapq.heappop(top_k)      # evicts smallest; k largest survive!

# 5. Built-in helpers for one-shot top-k
heapq.nsmallest(k, items, key=lambda x: (-x.score, x.name))

To find the k largest numbers in a stream of 10 million integers using only O(k) memory, should your size-k heap be a min-heap or a max-heap?

Spot on! The root is the gatekeeper—the smallest of your top-k VIPs. Any newcomer bigger than the root kicks it out in O(log k).

With a max-heap of size k, the biggest element sits at the top, so you have no O(1) way to find and evict the smallest element when a bigger newcomer arrives. A min-heap keeps the eviction target right at index 0.

4bisect: exact boundaries without off-by-one bugs

Whenever an array is sorted, bisect_left and bisect_right give you bug-free binary search in one line. Hold this single picture in your head:

index:          0    1    2    3    4    5
sorted array: [ 1,   5,   5,   5,   9,  12 ]
                     ↑              ↑
      bisect_left(a, 5) = 1   bisect_right(a, 5) = 4

Count of elements equal to 5:       4 - 1 = 3
Count of elements in [lo, hi]:      bisect_right(a, hi) - bisect_left(a, lo)
bisect_left lands at the first position where x could go (before existing xs); bisect_right lands after all existing xs.

In a = [2, 4, 4, 4, 8], what are bisect_left(a, 4) and bisect_right(a, 4)?

Right! Index 1 is the first 4, and index 4 is right after the last 4—so 4 - 1 = 3 copies of 4.

Remember: bisect_right returns the index past the last match, just like Python's half-open slices a[left:right]! For [2, 4, 4, 4, 8], the slice of 4s is a[1:4], so left=1, right=4.

You decorate def dfs(idx, visited): with @functools.cache and pass a Python set as visited. What happens?

Spot on! @cache puts all arguments into a dict key, so every argument must be hashable—pass an immutable frozenset, tuple, or integer bitmask instead.

Under the hood, @cache keys an internal dict by the tuple of arguments. Mutable containers (list, set, dict) aren't hashable—convert to tuple, frozenset, or an int bitmask.

✓One-page cheat sheet checklist

  1. Queue / sliding deque: deque (append, popleft, pop, appendleft — all O(1)).
  2. Counting & grouping: Counter(xs), defaultdict(list), dict.get(k, 0).
  3. Priority queues: heapify O(n), heappush/heappop O(log n), negate for max-heap, min-heap of size k for top-k largest.
  4. Sorted binary search: bisect_left (first ≥ x), bisect_right (first > x), range count = bisect_right(hi) - bisect_left(lo).
  5. DP & streams: @functools.cache (hashable args only!), accumulate, pairwise, islice, cmp_to_key.
