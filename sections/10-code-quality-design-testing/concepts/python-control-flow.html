1Variables, basic values, and indentation

Python runs a file one line at a time, from top to bottom. To store a value, write a name, an equals sign, and the value — there is no type or declaration keyword like int or let, and no semicolons at the end of lines:

age = 25              # whole number (int)
price = 4.50          # decimal number (float)
name = "Maya"         # text (str)
is_member = True      # True or False (bool)
coupon = None         # means "no value here yet"

Instead of curly braces { }, Python uses indentation (4 spaces) to show which lines belong inside a decision, loop, or function. Whenever a line ends with a colon (:), the indented lines right below it belong to that block; stepping back to the left ends the block:

if is_member:
    print("Welcome back,", name)   # inside the if block
    price = price - 1.00           # also inside the if block

print("Total:", price)             # back on the left: always runs!

Want every operator and type conversion in one lookup table? Bookmark Python Cheatsheet §1 (Basics).

With names and indentation in place, let's look at how Python chooses between multiple paths.

2Making decisions with if, elif, and else

Picture pricing a movie ticket by age: kids under 12 pay $8, regular tickets (ages 12–64) cost $14, and seniors 65 or older pay $10. Each customer should match exactly one price.

In Python, chain if → elif ("else if") → else. The instant Python finds a matching branch, it runs that block and skips every branch below it. Writing two separate if statements instead checks both conditions independently — one of the easiest ways to overwrite your own answer by accident:

Use elif whenever only one branch should win; use separate if blocks only when multiple checks can apply at the same time.
if age < 12:
    ticket = 8
elif age < 65:
    ticket = 14
else:
    ticket = 10

To test equality inside a condition, use two equals signs (==) and != for "not equal" (a single = stores a value, while == compares two values). Four small Python habits make everyday conditions much cleaner to read:

  • Chained comparisons: write if 13 <= age <= 19: just like normal math, instead of repeating age >= 13 and age <= 19.
  • Left-to-right short-circuiting: with and, Python stops the moment the left side is False. In if people > 0 and total / people > 20:, when people is 0, Python stops early and never divides by zero.
  • Truthiness and is None: inside an if, empty text "", zero 0, False, and None all act like False (Python calls these falsy), while non-empty text and non-zero numbers act like True. Write if name: to check that a user typed something — but whenever 0 is a valid value (like a test score of 0), write if score is not None: so zero doesn't get treated as missing!
  • 1-line conditional expression: when picking between two values, you can write value_if_true if condition else value_if_false on one short line.
# Clean everyday checks
if 13 <= age <= 19:
    group = "teen"

if people > 0 and total / people > 20:    # safe: never divides by 0
    note = "large share"

if score is not None:                     # keeps score == 0!
    print("Recorded score:", score)

shipping = 0 if order_total >= 50 else 6  # free shipping at $50+, else $6
Use if / elif / else when only one branch should run, == / != for comparisons, chained range checks like 13 <= age <= 19, and is not None whenever 0 or "" is a real value you want to keep.

You run this weather check with temp = 105. What value does label end up holding?

label = "cool"
if temp >= 95:
    label = "hot"
if temp >= 70:
    label = "warm"

Spot on! Two separate if lines run one after the other: 105 >= 95 sets "hot", and then 105 >= 70 is also True and overwrites label to "warm". Changing the second if to elif fixes it.

Try a second example with score = 92: if you write if score >= 90: grade = "A" followed by a separate if score >= 80: grade = "B", Python checks both lines top to bottom — setting "A" first and immediately overwriting it with "B". Only elif skips later checks once an earlier branch matches.

Decisions let your code pick a path once. Next, let's repeat an action cleanly over a known sequence of steps or items.

3Repeating a known number of times with for and range

Whenever you know up front how many times to repeat — or you already have items to walk through — reach for a for loop.

To count through numbers, Python gives you range(start, stop, step). Memorize one rule and you will never get tripped up by range again: range starts at start, jumps by step each time (default +1), and stops right before hitting stop (the stop number itself is never included).

  • range(4) starts at 0 and stops before 4 → produces 0, 1, 2, 3 (4 steps total).
  • range(1, 5) starts at 1 and stops before 5 → produces 1, 2, 3, 4.
  • range(0, 8, 2) jumps by +2 → produces 0, 2, 4, 6.
  • range(4, -1, -1) uses a negative step (-1) to count backward from 4 down to 0! Because the stop number is never included, you must set stop = -1 if you want the countdown to reach 0 (similarly, step = -2 counts down by 2s).
# Count 1, 2, 3
for num in range(1, 4):
    print("Round", num)

# Rocket countdown: 3, 2, 1, 0!
for sec in range(3, -1, -1):
    print(sec)

Step through the countdown below and watch why range(4, -1, -1) finishes cleanly while range(4, 0, -1) stops one step too early:

Switch the dropdown between safe range(4, -1, -1) and buggy range(4, 0, -1). The stop number acts like a wall you stop before touching — whether counting up or down.

You don't need range when you already have items to visit. Python lets you walk straight through the characters of a string — or through a list of values inside square brackets [...] (we'll explore lists in depth in Part 2):

# Walk each character of a word directly
for letter in "hello":
    print(letter)

# Walk each name in a list directly — no counter variable needed!
guests = ["Maya", "Sam", "Kai"]
for guest in guests:
    print("Welcome,", guest)
Walk items directly (for guest in guests:) when you just need each value. When counting with range(start, stop, step), remember that step sets the jump size and stop is never included — so counting down to 0 always uses stop = -1.

Which numbers does this loop print?

for n in range(6, 0, -2):
    print(n)

Exact! Just like range(0, 6, 2) prints 0, 2, 4 and stops before 6, counting backward with range(6, 0, -2) stops before 0. Use range(6, -1, -2) to include 0.

Think about counting up first: range(0, 6, 2) prints 0, 2, 4, then sees the stop wall 6 and stops. Counting down follows the exact same rule: range(6, 0, -2) prints 6, 4, 2, sees the stop wall 0 next, and halts.

A for loop handles every job where the number of steps or the items are known up front. What about when you don't know ahead of time how many turns a loop will take — or when you want to stop a loop early?

4Looping on a condition with while, continue, break, and else

Switch from for to while condition: whenever a loop needs to keep going until something changes. Imagine you have a $15 coffee gift card and every coffee costs $4. You don't need to divide ahead of time — just keep buying a cup while balance >= 4 (note: balance -= 4 is shorthand for balance = balance - 4, and cups += 1 is shorthand for cups = cups + 1):

balance = 15
cups = 0

while balance >= 4:
    balance -= 4       # spend $4: 15 -> 11 -> 7 -> 3
    cups += 1          # count the cup: 1 -> 2 -> 3

print("Bought", cups, "cups; left with $", balance)
# Bought 3 cups; left with $ 3

Notice the golden rule of every while loop: something inside the loop must move the condition closer to becoming False. Here, balance -= 4 shrinks balance on every turn until it drops to 3 and the loop ends. Forget that line and the loop runs forever.

Inside either a for or a while loop, three keywords let you steer the flow:

  • continue: skips the rest of the current turn and jumps straight to the next turn.
  • break: leaves the loop immediately.
  • for ... else: (or while ... else:): an optional block lined up under for (not under if!) that runs only if the loop finished without hitting break. Read else: here as "no break happened".
# continue: skip blank entries while greeting guests
for name in ["Maya", "", "Sam", "", "Kai"]:
    if name == "":
        continue                    # skip this turn, jump to next name
    print("Hello,", name)

# break + for ... else: search a guest list without a "found = False" flag
guests = ["Sam", "Kai", "Maya", "Leo"]
target = "Maya"
for guest in guests:
    if guest == target:
        print("Found", target)
        break
else:                               # lined up with `for`: runs only if break never fired!
    print(target, "is not on the list")

Step through the guest-list search below to see when the loop's else: block runs and when break skips it:

Switch between target = "Maya" (hits break, so else: is skipped) and target = "Zoe" (checks every guest with no break, so else: runs).

One classic bug to watch for right away: combining while with continue! If your continue sits above the line that updates your counter, the counter never changes and the loop freezes forever:

# BUG: freezes at step == 3 forever because `continue` skips `step += 1`!
step = 1
while step <= 5:
    if step == 3:
        continue       # jumps back to `while` while step is STILL 3!
    print(step)
    step += 1

# FIX: advance `step += 1` before `continue` (or use `for step in range(1, 6):`)
step = 1
while step <= 5:
    if step == 3:
        step += 1
        continue
    print(step)
    step += 1
Use while when you loop until a condition changes, and make sure every branch moves closer to stopping (especially right before a continue!). Use break to leave a loop early, and remember for ... else: runs only when break never happened.

What does result equal after this loop finishes?

result = "checking"
for color in ["red", "blue", "green"]:
    if color == "blue":
        result = "found"
        break
else:
    result = "missing"

Exact! Finding "blue" hits break, which leaves the entire for ... else block immediately without running else:, so result stays "found".

Compare with searching ["red", "green"] for "blue": the loop checks both colors, never hits break, and then runs else: to set "missing". Because "blue" IS in ["red", "blue", "green"], break fires and skips else: completely.

What happens when you run this while loop?

n = 1
while n <= 4:
    if n == 2:
        continue
    print(n)
    n += 1

Sharp catch! On n = 2, continue jumps straight back to while n <= 4: without ever reaching n += 1, so n stays 2 forever. Always advance your counter before continue — or use for n in range(1, 5):.

Picture an even shorter countdown starting at t = 3: if the loop skips t == 3 with continue before t -= 1 ever runs, t never changes from 3! Here the exact same trap strikes at n = 2, freezing forever after printing 1.

Now imagine you want to reuse a chunk of logic in several places — or exit cleanly out of two loops nested inside each other. That is where functions shine.

5Packaging reusable steps into functions with def and return

A function gives a name to a block of code so you can run it whenever you need it. Define it once with def, pass inputs as parameters, and hand back the answer with return:

def order_total(price, qty=1, discount=0):
    return price * qty - discount

order_total(5)                 # 5  — uses qty=1 and discount=0
order_total(5, 3)              # 15 — 3 items at $5 each
order_total(5, discount=1)     # 4  — keyword argument lets you skip qty!

Default values (like qty=1) make optional inputs effortless, and keyword arguments (like discount=1) make function calls self-documenting so you never have to guess what a bare number means.

Three habits make Python functions click right away:

  1. return sends a value back; print() only shows it on screen. If a function finishes without hitting return, Python quietly hands back None. A classic beginner surprise is writing print(total) instead of return total and wondering why bill = calc_total(...) ends up as None!
  2. Returning two values at once. Separate them with a comma — Python bundles them together (into a fixed pair called a tuple, which we cover in Part 2; you may also see parentheses like (each, tip)) and lets the caller unpack them cleanly in one line: 
    def split_bill(total, people):
    each = total / people
    tip = total * 0.15
    return each, tip

share, tip = split_bill(60, 3)   # share is 20.0, tip is 9.0
  3. Exiting nested loops cleanly with return. Suppose rows is a list of theater rows (like [["taken", "free"], ["free", "taken"]]), counting from 0 just like range: len(rows) gives the number of rows, rows[r] gives row r (so len(rows[r]) is how many seats are in it), and rows[r][s] checks seat s in row r (we unpack list indexing thoroughly in Part 2). A break inside the inner seat loop only leaves the current row — the outer loop immediately moves on to the next row! Wrapping the search in a function lets return r, s exit both loops at once:

Clumsy: break only exits one loop

found = False
spot = None
for r in range(len(rows)):
    for s in range(len(rows[r])):
        if rows[r][s] == "free":
            spot = (r, s)
            found = True
            break          # exits inner loop only
    if found:
        break              # need a second break!

Clean: helper def + early return

def find_free_seat(rows):
    for r in range(len(rows)):
        for s in range(len(rows[r])):
            if rows[r][s] == "free":
                return r, s   # exits BOTH loops!
    return None
Optional preview: flexible arguments with *args and **kwargs

Later, when writing wrapper functions and decorators (Day 3), you will see *args (collects any number of positional arguments) and **kwargs (collects any number of named keyword arguments). You don't need them on Day 1 — they are also summarized in Python Cheatsheet §6 whenever you want a quick peek.

Always use return (not print) to hand answers back from a function, use default and keyword arguments to keep calls readable, and wrap nested searches in a helper function so return exits every loop cleanly in one line.

What does ans hold after calling ans = double_price(6)?

def double_price(price):
    total = price * 2
    print(total)

Spot on! print(total) writes 12 to the console, and because the function ends without a return total statement, ans receives None.

Compare with def add_tax(x): print(x + 1): calling bill = add_tax(10) prints 11 on screen for a human to read, yet hands None back to bill because nothing was returned. Only return total sends 12 back to ans.

Suppose rows = [["taken", "free"], ["free", "taken"]]. You loop over each row and each seat, and when you see "free" you set spot = (r, s) and call break — with no second break on the outer loop. What does spot end up holding?

Caught it! break only stops the innermost loop (the seats in row 0). The outer loop still moves on to row 1, finds "free" at (1, 0), and overwrites spot. Putting the search inside a function and writing return r, s exits both loops cleanly.

Picture checking a 2-floor hotel room by room: finding an open room on floor 0 and hitting break only stops checking the rest of floor 0 — you still walk upstairs to floor 1! So here row 0 sets spot = (0, 1), then row 1 runs anyway and overwrites spot to (1, 0). Use return r, s inside a function to leave immediately.

Now that you can write clean functions, there is one last control-flow skill to pick up: what should your function do when someone hands it bad input, or when an operation like converting text to a number might fail?

6Guarding bad inputs and catching errors safely

Sometimes an input makes no sense — like ordering -3 coffees or asking for a countdown from -5. Instead of quietly returning a bogus answer, fail loudly right at the top of your function with raise ValueError(...):

def order_total(price, qty=1):
    if qty < 0:
        raise ValueError("qty cannot be negative")
    return price * qty

On the flip side, when you call something that might legitimately fail on messy input — like turning user text into an integer with int(text) — wrap only the risky line in try / except and name the exact error you expect:

def parse_age(text, default=None):
    try:
        return int(text)            # works for "25", fails for "twenty"
    except ValueError:              # catches ONLY bad number text!
        return default

Never write a bare (blank) except: with no error name after it. A bare except: catches everything — including your own typos like spelling text as txet (NameError) — turning an obvious typo into a silent bug that takes 20 minutes to find.

Guard invalid inputs at the top of a function with raise ValueError("..."), and catch only the exact exception you expect (like except ValueError:) so typos never get swallowed.
